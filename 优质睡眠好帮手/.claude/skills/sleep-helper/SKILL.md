# 优质睡眠好帮手（sleep-helper）

把一个需要长时间自主执行的任务，在动手前拆解到"问无可问"，冻结成一份可无人值守执行的任务书，并在执行中设置超时与熔断。目标是让开发者在睡醒后直接拿到结果，而不是中途被叫起来做决策，或发现 agent 卡死。

触发后按下面四步走；每一步的产出都是下一步的输入。

## 1. 树状深挖：出框架 → 逐层细化 → 刨根问底

动手写任何代码、执行任何命令之前，先把任务建构成一棵由浅入深的决策树。

- **第一步，出大框架**：用一句话写出最粗的闭环。例如 "MCU 控制 boost 输出固定电压" 的大框架是：ADC 读取 → PID 计算 → MCU 输出占空比 → 再次采样 → 循环。
- **第二步，逐层细化**：对框架里每个节点追问"怎么做 / 用什么方式"。例如 ADC 用 DMA 还是软件直接读？PWM 频率取多少才能兼顾纹波与效率？PID 用增量式还是绝对式？
- **第三步及以后，继续下钻**：采样频率多少合适？ADC 用多少 cycles？怎么滤波？DMA 双缓冲还是单缓冲？PID 要不要限幅？主要靠 P 还是 I？……
- 如此往复，直到每个叶子节点都是一条无需再决策、可直接执行的明确指令，即"问无可问"。

**每一层都遵循"最少人工摩擦"原则**：凡是有多条技术路线的地方，优先选不需要人工操作的那条——
- 不需要下载/安装额外软件、不需要 GUI、不需要人工点选的方案优先（例：前端用 HTML/Web+JS，而非必须装 Visual Studio 才能跑的方案）。
- 现成环境优先于新建环境（例：已有 venv 直接用，不重造）。
- CLI / 脚本化 / 无头优先于图形界面交互。
- 常见、成熟的方案优先于冷门方案，减少意外。

**何时问用户**：只有当某个决策确实无法凭上述原则或常识自行定夺（如需要账号、真实硬件参数、明确偏好）时，才停下来向用户提问，并把答案记入任务书。目标是"一次问完"，不让同一类问题在执行中途反复出现。

## 2. 卡点预判：把"会卡住"的地方提前想清楚

深挖的同时，标记任务里所有"可能长时间阻塞或死循环"的操作——编译、安装依赖、下载、启动服务、跑测试、连设备等。

对每个这样的操作，在执行前写清楚三件事：
- **预期耗时**：正常应该多久出结果。
- **超时阈值**：超过多久仍无结果就判定异常。
- **判定与应对**：超时后先看日志，区分三种情况——
  1. 终端真卡死 / 进程挂了 → 停止，排查代码或重跑；
  2. 模型精度不足导致的"无意义循环"（反复做同一件事无进展）→ 换策略，不重复同一动作；
  3. 实际在正常运行、只是偏慢 → 继续等。

**熔断规则**：同一操作连续失败或空转超过 N 次（默认 3 次）仍无进展时，必须换一条路，禁止原样重试。为所有长操作保留日志，供超时后判断用。

## 3. 冻结任务书：生成 任务书.md

把前两步的结论冻结成一份格式严谨的 `任务书.md`。它是后续执行的唯一依据，也是"醒来有结果"的保障。

- 按下面「任务书模板」的骨架逐段填写。
- 任务书必须包含：目标与成功判据、完整决策树（每一层"选什么、为什么"）、所有已解决的人工决策点及其答案、每个卡点操作的超时阈值与熔断规则、明确禁止中途询问用户的事项清单。
- 措辞面向 AI 执行者：指令式、无歧义、可机械执行，不含"视情况""酌情"等留白。

生成后按用户习惯作为目标交给执行（如 `/goal 任务书.md`）；若无该命令，则直接依据任务书逐条执行。

## 4. 执行与守夜

依据任务书开始执行。执行期间：
- 对每个标记过的操作启用超时与熔断（见第 2 步）。
- 出现任务书未覆盖的新情况时，优先用任务书里的原则自行解决；确实需要人的决定，才唤醒用户。
- 定期落盘中间结果，避免长时间运行后一次崩溃前功尽弃。

最终目标：开发者在运行期间无需干预，睡醒后直接拿到可用结果与一份清晰的完成 / 失败说明。

## 树状深挖示例

三个完整示例，用于校准下钻深度与"最少人工摩擦"原则。

**示例 1：MCU 控制 boost 输出固定电压**
- 第 1 层（大框架）：ADC 读取 → PID 计算 → MCU 输出占空比 → 再次采样 → 循环。
- 第 2 层（细化）：ADC 用 DMA 还是软件直接读？PWM 频率多少才能兼顾纹波与效率？PID 增量式还是绝对式？
- 第 3 层（深化）：ADC 采样频率多少？用多少 cycles？怎么滤波？DMA 双缓冲还是单缓冲？PID 要不要限幅？主要靠 P 还是 I？
- 第 4 层（刨根问底）：滤波用滑动平均还是卡尔曼？要不要低通？ADC 采样周期会不会和 PID 计算周期重叠冲突？
- ……如此往复，直到每个叶子都能直接写成一条 C 代码指令。

**示例 2：环境选择（venv vs conda）**
- 用现成的还是新建？→ 优先现成。
- 若需新建：venv 还是 conda？→ 已装哪个用哪个，都没装则用 venv（更轻、无额外安装）。
- pip 包没有怎么办？→ 先看有无离线 / 内置替代，再考虑下载；下载要有超时与镜像回退。

**示例 3：前端实现（VS vs HTML vs Web+JS）**
- 用什么做前端？Visual Studio / 原生 HTML / Web+JS？
- 按"最少人工摩擦"：HTML/Web+JS 不需要额外安装软件、可直接产出，更适合 AI 自主开发；Visual Studio 需要安装与 GUI 操作，优先级最低。
- 结论：默认 HTML/Web+JS；除非用户明确要求桌面原生。
